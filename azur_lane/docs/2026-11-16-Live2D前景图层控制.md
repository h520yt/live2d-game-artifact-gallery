# Live2D 前景遮挡图层控制（ArtMesh）

## 问题实例

- 角色：企业，`qiye_10`（Bathing Under Sunny Skies）。
- 动作：`idle9`。用户截图显示前景出现大面积深绿色植物叶片，覆盖人物身体和部分脸部。
- 原有 `fixSolidMask` 仅在**模型第一次载入**时处理部分纯色遮挡层，不处理动作中途才出现的普通植物 ArtMesh。
- 仅凭截图不能知道叶片在模型内的 ArtMesh ID；原始模型和纹理未上传，也未提交仓库，因此不能安全硬编码隐藏编号。

## 使用方法

1. `git pull origin main`，从项目根启动 `python -m http.server 8000`，打开 `/azur_lane/viewer/index.html`。
2. 在 **Live2D 模型** 搜索 `qiye_10` 并打开。右上角动作菜单点 `idle9`，收起菜单。
3. 左下角新增 **「前景图层」** 按钮。展开后点击 **「试隐藏前景」**，实时查看绿色叶片是否减少。此操作按可见度、渲染顺序与 ArtMesh 几何面积挑选最多四个前景候选，并不保证全为树叶。
4. 需要精确调整时使用 **「显示全部图层」**，搜索 ID / 序号，逐个点击 **「隐藏 / 恢复」**。面板会显示图层序号、名称、前后顺序和面积比例；按完可立即观察角色画面变化。
5. 如果隐藏错了头发或衣服，点击 **「全部恢复」**，恢复当前模型当前动作的全部手动隐藏。
6. 该组隐藏 ID 自动保存到浏览器 `localStorage`：`azurlane.artmesh.hidden.v1`，以 `qiye_10::idle9` 为 key。下次播放该动作时自动应用；其他动作互不影响。

**说明**：这是可逆的渲染层过滤，不修改 `.moc3`、纹理、动作文件或原始 Bundle。清空浏览器本地存储会清除保存的设置。

## 技术实现

- 模型初始化后，在 Cubism `internalModel.update` 后串接隐藏处理；不覆盖已有 `fixSolidMask`。
- 从 CoreModel API 读取 drawable ID / order / alpha / 轮廓；候选筛选只提供可逆试隐藏，默认**不会自动隐藏任何图层**。
- 用户主动播放动作时切换隐藏配置，待机动作循环结束后仍保持所选图层的隐藏。缓存模型再次打开会恢复默认作用域。
- 单独存储的是 **ArtMesh ID**，而非不稳定的数字索引。若后续更新模型导致 ID 改变，旧规则自然失效，不会误伤另一个 ID。
- 同一幅纹理图集中的不同 ArtMesh 也可单独隐藏；但同一个 ArtMesh 内绘制的主体与叶片无法仅靠隐藏图层拆分。
- 图层列表只展示前 80 个匹配项，可通过搜索缩小范围；候选识别基于面积、渲染顺序和名称，不做图像识别，不保证自动消除所有植物。

## 适用范围和风险

此功能适用于独立前景叶片、烟雾、道具、部分遮罩和过场绘制层。若绿色叶片与角色共用 ArtMesh，隐藏它可能令人物局部残缺；需撤销并另外处理贴图/分层资源。被遮挡区域缺少真实人物绘制时，隐藏叶片也不能生成原本不存在的图像。

当前实现已增加 Node 逻辑测试（候选过滤、动作作用域、前端接线），**没有在用户本地的 `qiye_10` 实际模型上验证叶片 ArtMesh ID**。确认最终效果时建议记录操作后实际隐藏的 ArtMesh ID，后续可据此加入一键预设，无需反复手动尝试。
