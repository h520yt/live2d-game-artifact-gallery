# 皮肤展示柜统一展示标准

适用于当前四款游戏与后续接入的新游戏。UI 和资源内容解耦，**不为单次批次、价格档位、新角色单独创建导航或页面**。

## 统一交互

1. **统一卡片列表**：展示每套皮肤一张卡片，角色名称、衣着名称、封面和真实本地状态。支持搜索、排序；同款不同模型形态合并到详情内。
2. **独立大舞台**：点击卡片进入视口内的全屏详情层，优先展示已验证完整场景图；可切换可用 Live2D/Spine/静态模式。动作、姿态、交互、特效设置按需展开，不占据首页。
3. **返回原位**：详情以覆盖层展示，不重建或滚动原列表；支持 Esc / 返回按钮 / 上下套皮肤。
4. **资源真实性**：仅当真正有角色与场景的完整图且校验通过时才展示封面，禁止将背景层、图集碎片、错角色图片伪装为整图。未安装资源显式提示，不虚构文件。
5. **单画廊，按游戏区分**：每款游戏只保留自己的一处皮肤画廊。来源、价格、档位、批次可以是内部检索元数据，但不会自动产生独立页面、顶栏分类或重复卡片。用户明确要求专题时除外。
6. **风格偏好游戏独立**：黑丝、御姐、鞋履、腿部关注等仅应用于指定游戏的采集筛选；不会传播到《重返未来：1999》或新游戏。

## 公共实现

- `shared/skin_gallery.css`：统一卡片/大舞台/浮动控制抽屉布局。
- `shared/skin_gallery.js`：标准目录、搜索/排序、同 ID 去重、打开/关闭、上一套/下一套、滚动位置保留。
- `shared/gallery_bridge.js`：跨游戏全局索引到专属查看器的精准深链，保留 `gallery_asset` 入口。
- `scripts/new_game.py`：新游戏默认创建以上公共布局和静态预览；游戏专属的动画播放器仍独立实现。
- `reverse1999/viewer/index.html`：已经改用公共卡片列表，并将 UNIQUE、点唱机、普通模型合并。
- `gallery_core/catalog.py`：1999 同一皮肤的不同 renderer 不重复计数。
- `reverse1999/scripts/sync.py`：`data/full_scenes/<skinId>.png` 是每个 skin ID 的可选完整场景资源，不限价格档次。

现有碧蓝航线与棕色尘埃 2 已采用卡片→大舞台的交互形式。它们各自的模型和交互逻辑不会为统一视觉而被重写，后续 UI 收敛应通过公共布局逐步替换，不破坏已验证动作与素材。

## 新游戏接入要求

生成：

```powershell
python scripts/new_game.py --id new_game --title "新游戏"
```

填入 `games/new_game/viewer/manifest.json` 后执行：

```powershell
python scripts/gallery.py serve
```

仅在 `games/new_game/viewer/viewer.js` 实现引擎特有的下载、模型加载、动画、触摸动作与画面合成。**不创建新的一套卡片/详情/返回定位代码**。资源、动作或图像缺失时必须保留诚实状态。
